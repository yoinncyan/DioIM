# **需求 & 项目管理规范（整理版）**

## 1. Issue 提交规范（git 出 issue）

**Issue: `<id>`**

Issue 内容需包含以下部分：

### **① 任务背景 / 目的（Why）**

说明为什么要做这项任务，包括业务背景、体验问题或设计要求。

### **② 设计说明（What）**

清晰描述本次任务涉及的 UI/功能调整，包括视觉、文案、布局、组件改动等。

### **③ 交互规则（Interaction）**

如有交互变化，需明确说明动作逻辑、动画细节、状态切换等。

### **④ 开发注意点（Dev Notes）（可选）**

提供开发阶段需要特别留意的点，例如：

* 兼容性要求（暗黑模式、不同机型）
* 布局适配
* 性能风险
* 依赖组件或资源说明

---

## 2. 看板管理 & Issue 绑定规范（任务管理）

任务需绑定到项目看板，并进行人员分配。

要求：

* Issue 创建后，需同步到看板
* 为 Issue 指定负责人和评审人
* 在流程中按阶段推进（ToDo → In Progress → Review → Done）
* 保持看板状态与 PR / Issue 状态一致

---

## 3. PR 提交规范

PR 须关联到 Issue：

* `issue: <id>`
* `issue: <link>`

PR 描述内容应包含以下部分：

### **① 变更摘要**

概述此次 PR 的主要改动（功能优化、UI 调整、Bug 修复等）。

### **② 影响模块**

列出受影响的模块、组件或页面，便于评审和测试关注重点。

### **③ 测试证据（截图 / 录屏）**

必须提供展示变更效果的截图或录屏，并说明验证的场景，例如：

* 浅色/深色模式
* 不同机型兼容
* 多语言验证（如适用）
